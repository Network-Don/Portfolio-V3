Network Segmentation & VLAN Deployment for a Regulated Microfinance Bank

Redesigned the flat, unsegmented network of a CBN-regulated microfinance bank into 11 isolated VLANs with zone-based firewall policy, QoS-prioritized core banking traffic, and full inter-VLAN routing — closing a compliance gap ahead of a regulatory audit and hardening the network against lateral movement from a single compromised endpoint.

Network architecture diagram for the VLAN segmentation deployment. Device identifiers and production-specific labels have been sanitized.

Problem Statement

The client, a CBN-licensed microfinance bank, operated its head office and branch on a single flat network with no segmentation between departments, servers, or endpoints. As a regulated financial institution, this represented a direct compliance risk — CBN IT audits require demonstrable access segregation between sensitive functions, and failure to remediate this class of finding can put an operating license at risk. It was also a serious security exposure: any single compromised device had unrestricted access to every server and administrative system on the network, and the client's endpoint protection platform was known to be unreliable, meaning network-level controls had to carry the primary security burden rather than act as a backup layer. Compounding this, there was no existing documentation of switch port assignments, department boundaries, or device inventory anywhere on the network.

My Approach

  1. Discovery & Site Assessment

    Conducted a full physical and logical audit of the head office and branch: traced every switch port to its connected device, inventoried all network hardware (switches, firewall, servers, local office switches), documented existing (lack of) segmentation, and captured current DHCP configuration. Used a structured site assessment template to ensure nothing was missed, including physical security observations (unlocked server rooms, unlabelled cabling, default credentials).

  2. VLAN & IP Address Design

    Designed an 11-VLAN segmentation model aligned to departmental and functional boundaries, standardizing every VLAN to a /24 subnet for predictable, easy-to-document address boundaries and long-term growth headroom.

  3. Firewall-First Configuration Sequence

    Configured VLAN sub-interfaces, DHCP scopes, and zone-based firewall rules on the perimeter firewall before touching the switch trunk configuration — a sequencing decision that proved critical during rollout. Grouped VLANs into security zones (Management, Restricted, Internal, Branch) so firewall policy could be written and audited at the zone level rather than per-VLAN, improving both manageability and auditability.

  4. Switch Configuration & Port Mapping

    Physically traced and mapped every port on the core switch and on the small local switches serving each office to its connected endpoint, since no prior port documentation existed. Configured VLANs, trunk ports, and access ports on the core managed switch, migrating departments one VLAN at a time with connectivity verification after each migration rather than a single bulk cutover — minimizing blast radius if a misconfiguration occurred. Assigned the core switch a dedicated management IP on a restricted management VLAN, accessible only from the IT segment, to support ongoing administration without exposing the switch's web interface to the wider network.

  5. Radio Link Extension

    Verified the inter-site radio link was operating in Layer 2 bridge mode (a prerequisite for 802.1Q VLAN tags to traverse it) and confirmed MTU support for tagged frames before extending the branch VLAN across it. Configured the branch switch as a mirror of the relevant HQ trunk configuration, restricted to the single VLAN required for that site.

  6. Inter-VLAN Routing (ROAS) for Shared Resources

    Beyond basic zone isolation, configured specific inter-VLAN routing rules on the firewall to permit controlled access to shared resources — such as network printers not present in every office — so departments without a local printer could still reach one on another VLAN, without opening broader lateral access between those segments.

  7. Server Addressing & Reachability

    Assigned static IP addresses to all core infrastructure servers — file server, application server, and database server — replacing ad hoc or DHCP-assigned addressing. This ensured consistent reachability for firewall rules, DNS records, and application configuration, and eliminated the risk of a server's IP changing on lease renewal and breaking dependent services.

  8. Quality of Service (QoS)

    Implemented QoS policy on the firewall to prioritise and guarantee bandwidth for core banking application and website traffic over general internet browsing and best-effort traffic, ensuring transaction-critical systems remained responsive even under network load — particularly important on the bandwidth-constrained radio link to the branch.

  9. Lateral & Vertical Movement Hardening

    Given the client's unreliable endpoint protection, implemented compensating network-layer controls: switch port isolation to prevent intra-VLAN (horizontal) movement between devices in the same department, explicit zone-to-zone deny rules on the firewall to prevent cross-VLAN (vertical) movement, and native VLAN hardening to prevent VLAN-hopping attacks.

  10. Testing, Documentation & Handover

    Validated every VLAN independently (gateway reachability, correct DHCP assignment, server access per policy, cross-VLAN isolation, shared printer access) before sign-off. Delivered full documentation: IP addressing plans, switch port maps, firewall rule sets, and server/device static IP registers — structured for direct use in a CBN compliance audit.

Challenges & Solutions

Trunk-Before-Firewall Outage

An early misstep configuring the switch trunk before the firewall was ready caused a temporary loss of connectivity for several departments — resolved by rolling back and re-sequencing the entire deployment to firewall-first.

Zero Pre-Existing Documentation

Neither the core switch nor the small local switches in each office had any existing port documentation — every port had to be physically traced and mapped to its connected endpoint before VLAN assignment could begin.

Undocumented Radio Link Behaviour

The inter-site radio link's Layer 2/Layer 3 behaviour was undocumented and had to be verified directly with the vendor before branch segmentation could safely proceed.

VLAN Isolation vs. Shared Printers

Strict VLAN isolation would have blocked departments without their own printer from reaching one in another office — required deliberately scoped inter-VLAN routing rules narrow enough to avoid reopening lateral movement risk, but permissive enough to preserve day-to-day workflows.

Outcomes

  • Flat network converted into 11 isolated, access-controlled VLANs
  • Branch office fully segmented across the radio link with zero access to HQ staff segments
  • Core banking application and website traffic prioritized via QoS for consistent performance under load
  • File, application, and database servers moved to static addressing for reliable reachability
  • Core switch secured with a dedicated, access-restricted management IP
  • Shared resources like printers remained accessible across departments through deliberately scoped routing rules
  • Network hardened against lateral and vertical compromise spread, compensating for unreliable endpoint protection
  • Full audit-ready documentation delivered ahead of the client's next regulatory examination
